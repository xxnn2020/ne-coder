# coder 演进路线规划

> 一个给程序员的终端编程 Agent。本文档基于当前功能盘点规划未来工作，按近期（P0）/中期（P1）/远期（P2）分期，每个条目可独立执行。

---

## 一、现状概览（规划基线）

| 模块 | 能力 |
|---|---|
| 对话引擎 | langchain createAgent + ChatOpenAI（OpenAI 兼容端点）、streamEvents 流式输出、多轮上下文、Ctrl+C 中断续问 |
| 工具体系 | 13 个本地工具（bash 跨平台/readFile 分段/writeFile/editFile/moveFile/deleteFile/grep/globFile/fetch/loadSkill/todoWrite/askUser/sum）+ 远程 MCP（单服务器故障隔离） |
| 交互输入 | 自绘输入框、`/` 指令补全、`@` 文件递归联想、↑↓ 输入历史、askUser（含 Y/N 确认模式）、todoWrite 任务清单渲染 |
| 指令系统 | 内置（help/clear/exit/quit/summary/vector）+ 自定义（`.coder/commands` 下 md，文件夹即指令） |
| 上下文体系 | 系统提示词模板（占位符）、用户/项目上下文（`.coder.md`）、skill 列表注入、`@文件` 注入（rules 规则 glob 匹配） |
| RAG | `/vector` 向量化（txt/pdf/docx/xlsx/md、md5 增量、双库存储、自愈重建）、对话自动检索、出处输出 |
| 会话管理 | 历史持久化（含 summary 与工具调用记录）、`-c` 继续最近会话、`-r` 列表选择恢复 |
| 配置分发 | `.coder` 体系（项目级优先/用户级兜底）、npm link 本地全局命令 |

## 二、近期（P0）：补短板与安全底线

### 1. 危险操作防护墙

- **背景**：bash/editFile/writeFile/deleteFile 已具备完整文件与命令能力，仅靠系统提示词约束模型行为，无硬性拦截。一次误删可能不可逆。
- **目标**：
  - 工具执行前的命令审查层：对 `rm -rf`、`git push --force`、`sudo`、工作目录外写入等高危模式拦截，经 askUser 确认后才放行
  - 权限模式配置（setting.json）：`confirm`（默认，高危必问）/ `yolo`（全部放行）
  - 审查规则可扩展：`.coder/rules` 体系下增加 `dangerous` 类规则，或独立配置文件
- **验收**：模型发起 `rm -rf` 类命令时出现 Y/N 确认；拒绝后模型收到拒绝原因并能改道；yolo 模式跳过确认
- **依赖**：无（基于现有 askUser 与工具层）

### 2. /model 指令与配置热切换

- **背景**：模型切换要手改 setting.json 并重启；DashScope 额度耗尽时无法快速换模型逃生。
- **目标**：
  - `/model` 列出可用模型（setting.json 配置 `models` 数组：名称/端点/密钥引用），`/model qwen-flash` 热切换（重建 agent 单例）
  - `/vector` 的 embedding 模型同样纳入管理；额度过限时给出候选提示
- **验收**：会话中切换模型后下一轮对话即生效，无需重启；agent 工具与上下文完整保留
- **依赖**：无

### 3. 长会话上下文压缩

- **背景**：messages 无限增长，长会话必然超出上下文窗口且 token 成本线性上升；目前仅有 /summary 手动摘要。
- **目标**：
  - token 预算管理：估算当前上下文长度，超阈值（如 80%）自动触发压缩
  - 压缩策略：旧轮次用摘要替代（复用 summarizeStream），保留最近 N 轮原文；工具调用记录折叠为一行描述
  - 会话中提示"已压缩早期对话（x 轮 → 摘要）"
- **验收**：人为构造超长会话，压缩后对话仍能引用早期关键信息，token 显著下降
- **依赖**：2（切换小模型做摘要更省）

### 4. RAG 检索增强

- **背景**：当前纯向量检索，问句式提问召回不稳定（阈值边缘抖动）；embedding 额度间歇耗尽时体验降级。
- **目标**：
  - 查询改写：检索前让小模型把口语问题改写为检索语句（关键词提取/同义扩展）
  - 混合检索：文件名/路径关键词匹配（复用 searchDirEntries）与向量检索并行，结果融合
  - 阈值自适应：按命中分数分布动态截断，而非固定 0.55
  - embedding 失败降级：额度耗尽时自动切换纯关键词检索，提示带标识
- **验收**："我在哪里上班"类问句稳定命中；库不存在/接口失败时关键词兜底可用
- **依赖**：2（查询改写用小模型）

### 5. 测试体系与发布准备

- **背景**：核心链路（配置加载、指令分发、md5 增量、消息转换）全靠手工冒烟，回归成本高；npm 发布前必须有底线。
- **目标**：
  - node:test 单测：fileUtils/vectorUtils（md5 分组/manifest 自愈）/llm（消息转换、恢复过滤）等纯逻辑模块
  - pty 集成测试脚本化（现有 script 命令流固化为用例）
  - first-run 引导：无配置时交互式引导生成 setting.json（端点/key/模型三项）
  - npm 发布清单：README、bin 校验、版本策略
- **验收**：`npm test` 覆盖核心纯逻辑；全新机器 `npx coder` 首启有引导流程
- **依赖**：无

## 三、中期（P1）：核心竞争力

### 6. git 工具链

- **背景**：git 操作全靠 bash 裸命令，模型生成 commit message 质量不稳定；本项目 CLAUDE.md 的"先提交再开发"工作流是高频刚需。
- **目标**：
  - `/commit` 指令：git diff 暂存区分析 → 生成规范化 commit message（类型/范围/描述）→ askUser 确认（可编辑）→ 执行提交
  - git 状态感知：启动时读取 git 状态，脏工作区时 banner 提示
  - 可选 `/pr`：基于 diff 与 issue 上下文生成 PR 描述
- **验收**：/commit 一条指令完成暂存+生成+确认+提交；message 符合约定式提交
- **依赖**：1（提交属可审查操作）

### 7. editFile diff 预览与批量确认

- **背景**：editFile/writeFile 修改直接落盘，用户看不到改了什么；出错回滚靠 git。
- **目标**：
  - 修改类工具返回结构化 diff，终端渲染（复用 logUtils 的对齐能力：+绿/-红）
  - 批量修改（一轮多文件）时汇总预览，一次确认全部或逐个确认
  - 会话内 undo：记录本次会话的文件修改对（原内容），`/undo` 回滚最近一轮
- **验收**：模型改 3 个文件时展示 3 个 diff 并一次确认；/undo 恢复原状
- **依赖**：1（确认机制复用）

### 8. subagent 子代理

- **背景**：复杂任务（全局重构、跨文件调研）单上下文来回翻文件效率低、上下文膨胀。
- **目标**：
  - `spawnAgent` 工具：主 agent 派生子 agent（独立 messages 与工具集），子 agent 完成调研/执行后只返回结论
  - 典型模式：Explore（只读调研，返回报告）/ Execute（执行子任务，返回结果）
  - 子 agent 运行时终端显示占位（"🔍 子任务：扫描 API 用法…"）
- **验收**：让主 agent"调研全项目 console.log 用法并汇总"，子 agent 承担扫描，主上下文只增加摘要
- **依赖**：3（子代理是上下文压力的解药，互补）

### 9. hooks 插件机制

- **背景**：工具执行前后的定制需求（自动格式化、审计日志、团队规范检查）散落在各处，没有统一扩展点。
- **目标**：
  - `.coder/hooks/` 下声明式 hook：`PreToolUse`（可拦截/改参）/ `PostToolUse`（可后处理）
  - hook 用 shell 命令或 js 模块实现，事件数据走 stdin/stdout JSON 协议
  - 内置示例：editFile 后自动 prettier、bash 前写审计日志
- **验收**：配置"writeFile 后运行 lint"生效；hook 返回非零时工具调用被阻止且模型收到原因
- **依赖**：1（防护墙是 PreToolUse 的内置特例）

### 10. 会话管理增强

- **背景**：-c/-r 只能按时间选会话；63 个历史文件后找特定对话靠肉眼。
- **目标**：
  - `/history [关键词]`：按摘要/首问搜索历史，列表选择恢复（复用 -r 的选择交互）
  - 会话命名：`/rename xxx`，列表显示名字；重要会话可置顶
  - 历史体积治理：自动清理 30 天前未命名会话（可配置）
- **验收**：/history 向量 搜到相关会话并恢复；命名会话不被自动清理
- **依赖**：无

## 四、远期（P2）：生态与差异化

### 11. skill 市场与一键安装

- **背景**：skill 目前手工放目录；社区复用缺失。
- **目标**：`/skill install <git-url|npm-name>` 拉取到 `~/.coder/skills/` 并校验 SKILL.md 规范；`/skill list/search`；安装来源与版本记录。

### 12. coder 作为 MCP server

- **背景**：coder 的工具链（向量检索、规则、文件工具）对其他 AI 工具有复用价值。
- **目标**：`coder --mcp` 以 stdio MCP server 模式启动，暴露 search/vectorize/readFile 等能力，供 Cursor/其他 agent 调用。

### 13. 多模态输入

- **背景**：前端调试（截图对比）、设计稿还原需要图像输入。
- **目标**：粘贴图片进对话（iTerm2 文件协议/剪贴板），vision 模型描述 + 读图提问；语音输入（whisper 类接口）。

### 14. IDE 集成（VSCode 扩展）

- **背景**：终端与编辑器切换割裂；选中代码提问、行内 diff 是高频诉求。
- **目标**：VSCode 扩展复用 coder 核心（node 子进程协议），提供选中即问、侧边对话、行内补全建议。

### 15. 团队配置同步

- **背景**：`.coder` 项目级配置已支持随仓库共享，但 skill/commands 更新靠人肉拷贝。
- **目标**：`coder sync` 从团队仓库拉取共享配置（rules/commands/skills），冲突提示；版本记录。

## 五、优先级总览

| 优先级 | 条目 | 一句话价值 |
|---|---|---|
| P0 | 1 防护墙 | 安全底线，不可逆操作的闸门 |
| P0 | 2 /model | 运维逃生与成本控制 |
| P0 | 3 上下文压缩 | 长会话可用性 |
| P0 | 4 RAG 增强 | 知识库命中率决定 RAG 价值 |
| P0 | 5 测试与发布 | 质量底线与分发 |
| P1 | 6 git 工具链 | 高频工作流一体化 |
| P1 | 7 diff 确认 | 改动透明与安全感 |
| P1 | 8 subagent | 复杂任务的扩展性 |
| P1 | 9 hooks | 团队定制扩展点 |
| P1 | 10 会话管理 | 历史资产可检索 |
| P2 | 11-15 | 生态、多模态、IDE |

**建议节奏**：P0 五项按序完成（约 1-2 周粒度/项）；P1 穿插进行，6 与 7 先行（直接提升日常体验）；P2 在 npm 发布且用户反馈积累后启动。
